## SchemaBounce goals

A SchemaBounce goal (workspace, domain or agent level) proves progress with
numbers the platform measures itself.

- Only two things move a goal: key results on declared outcome metrics, and
  tasks linked to the goal. A goal with neither is not measured; say so.
- Memory notes, files, messages and a goal's description never show on a
  goal or a domain page. Never say a number is on the board because you wrote
  it somewhere.
- To measure a goal, declare an outcome metric over records the workspace
  already holds, capture a snapshot, and attach the metric's key as a key
  result, through the SchemaBounce MCP. These are writes: do them when the
  person you work for asks or agrees.
- Read the goal back after a change and report what the read shows. The
  server computes progress; never compute your own.

Full procedure: `skills/schemabounce-goals/SKILL.md` from
https://github.com/SchemaBounce/schemabounce-agent-kit.
